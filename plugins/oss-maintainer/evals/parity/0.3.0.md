# 0.3.0 candidate validation

Date: 2026-09-06. Claude Code CLI on the maintainer's machine; Codex CLI 0.153.4 installed
without the candidate plugin (Codex parity not run for this version).

## Deterministic and structural checks

- 141 tests pass on Python 3.11 and 3.14 in CI. The run-record tests cover the four commands,
  the shared completion rule (an informational `not-applicable` item never blocks, a mandatory
  one blocks `show` and `finish` with the same reason), waivers, publication approval bound to
  the exact candidate, source versus artifact invalidation, reuse preserving the original
  execution, published digests kept separate, delivery reopening, atomic rejection of invalid
  input, and schema 1/2 records read without rewriting the file.
- The `pypi-library` gate test turns the fixture into a git repository with an untracked file
  and executes the documented recipe: the build runs in a worktree of `HEAD`, sees the committed
  module and not the untracked file, copies the artifacts back and removes the worktree.
- `bump.py --check`, the vendor guard, `claude plugin validate`, the agent-smith validator and
  `rebuild_index.py --check` pass.

## Direct behavioral scenario (Claude Code)

`release` on the `pypi-library` fixture, non-interactive (`claude -p --plugin-dir`), asked to
run steps 1, 2 and the GO proposal of step 4 without any publication, with the distribution
trigger still `TODO` in the profile.

| Behaviour | Result |
|---|---|
| One proposal at the first decision, with the coverage table and `run_record.py show` | passed: a single proposal named the version choice, the trigger to confirm and the fix path |
| Trigger detected from the Makefile and workflow, never run; no tag, push, PR or spend | passed: only `v1.0.0` exists, working tree clean, nothing pushed |
| Coverage table with real probes, observable success and prerequisites | passed: eleven rows, each with probe and expected result; unverifiable rows `not-run` with the reason |
| Record written with `new` and `set` only; `show` lists the GO blockers | passed: NO-GO named validator and package gate failed, owner checks and notes not run |
| Preflight surfaces environment problems before the GO | passed: validator cannot spawn pytest, wheel has no module, no remote for alerts, reported up front |
| Stops in a non-interactive session instead of writing or asking repeatedly | passed |

Observed and worth noting: the agent kept its record in a scratch clone rather than the
repository because the profile reported `release` incomplete; that follows the read-only rule.
It also reported findings outside the release diff as backlog for the owner's agreement, not
as release work.
